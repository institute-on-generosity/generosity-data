Vector search

flowchart LR
  Q["Mission"] --> E["Embed"] --> V["HNSW search"] --> M["Merge"]
  Q --> K["Keyword search"] --> M
  M --> C["Claude scores top 40"]
  • Embedded: mission + programs, 513,813 filings.
  • Model: nomic-embed-text-v1.5Open-source model from Nomic AI. Runs on our machine. Free, no API key. Makes 768 numbers per text. We keep the first 512, which it is trained to allow., local, 512 dimensions. Cloud: OpenAI text-embedding-3-smallOpenAI's paid embedding model, via its API. About $0.02 per million tokens. Returns 512 numbers directly. Nothing to run on our side..
  • Index: HNSW cosineFinds the closest vectors without checking all 473,474. HNSW links each vector to its near neighbors, and a search hops along those links. Cosine scores how alike two vectors are, here two missions. on filing_latest, the newest filing per org.
  • Model switch: re-embeds only stale rows, via embedding_model.
  • GrantRadar: mission → 150 closest grantees → their funders.

Limits

  • Text: only orgs that e-file a 990 (473,474 of 1.97M).
  • Years: IRS 2023 to 2025 (tax years mostly 2022 to 2024).
  • Recipients: no EIN on grants. 57% matched by name.
  • Individuals: not on any 990.

Moving to the cloud

  1. Get

    GitHub Actions, monthly

    Download public files

    • Raw IRS files?Every e-filed 990, as XML in monthly zips. 10 to 15 GB a year. Read once, then deleted.
    • Census files?County poverty, income and population, plus a ZIP to county table. Small, yearly.

  2. Clean + load

    GitHub Actions, monthly. Tested on your Mac first

    Pull ~40 fields from each return into rows

    • ETL scripts?Python that reads each return and writes the fields we keep into tables. One script per source.
    • Postgres staging?A copy of the database on your Mac. Test a new load here first, then copy it to Supabase. Nothing public reads it.

  3. Embed

    OpenAI or Voyage servers, not ours

    Turn each mission into 512 numbers. The ETL sends filings, the apps send questions.

    • Embedding API?Runs on OpenAI or Voyage servers. We send text over the internet and get 512 numbers back. Similar missions get similar numbers. Nothing to install or keep running.

  4. Store

    Supabase

    One shared database: tables and vectors together. Every app reads it.

    • Postgres + pgvector?Tables and vectors in one database. pgvector adds a vector column, so one query can mix "similar mission" with "in Ohio, under $1M". No separate vector database.
    • Auth?Supabase's login system, for accounts and saved searches.
    • Daily backups?A full copy each day, to restore after a bad load or a mistake.

  5. Serve

    Vercel

    Apps and API answer searches

    • NomBot?Search for nonprofits by mission, place and size.
    • GrantRadar?Find funders that paid groups like yours.
    • Public API /api/v1/search?JSON search anyone can call, limited to 60 requests a minute. The only public door. The database stays private.
    • Claude API?Anthropic's model. Reads the question, scores results, writes explanations.

  6. Use

    People and partner apps

    • Donors, nonprofits, developers?Reach the apps and the public API. Never the database.
    • Philanthro Map?Tyler's map. Reads the database directly with a read-only role: a login that can read but not change data.

Code

  • GitHub?Holds all code and migrations (numbered SQL files that change tables the same way everywhere). Each push deploys the apps to Vercel.
  • Secrets?API keys, stored encrypted in GitHub and Vercel. Never in the code.

Your Mac

  • Dev servers?The apps running at localhost while you build and test.
  • Experiments?Free GPU embedding and trial loads, before anything reaches Supabase.
  • APIs: only /api/v1/search is public (rate-limited). The database is never public.
  • Stay small: vectors for the newest filing per org only. halfvec halves their size.
  • Cost: Supabase with 4 to 8 GB of memory, ~$60 to $110 a month. ETL on GitHub Actions, free.

How big it gets

TodayWorst case
Vectors514K~2M (every org)
Vector index~1.5 GB~3 GB (halfvec)
Database11 GB~30 GB (10 IRS years)

pgvector is comfortable to ~10M vectors on one server, 5x our worst case. The limit is memory: the index should fit in RAM. Split grants by year past ~20M rows.
